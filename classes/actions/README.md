# Action Execution System

This directory contains the classes responsible for executing actions triggered by dynamic rule resolutions.

## Overview

The action execution system provides a safe and validated way to automatically execute corrective actions when dynamic rules fail. Actions are generated by the `action_generator` class and executed through specialized handler classes.

## Architecture

### Action Flow
1. **Rule Fails** → Dynamic rule execution detects a failed check
2. **Resolution Generated** → Dynamic resolution creates action button details
3. **Action Generator** → Creates standardized action button with validation
4. **User Triggers** → User clicks action button in audit interface
5. **Action Validator** → Validates permissions and safety
6. **Action Handler** → Executes the specific action type
7. **Result** → Returns success/failure with user-friendly message

### Core Classes

#### `action_validator.php`
- **Purpose**: Validates action permissions and safety before execution
- **Key Methods**:
  - `validate_action()`: Comprehensive validation of action parameters
  - `can_execute_actions()`: Check if user has basic permissions
  - `get_available_actions()`: Get list of actions available to user
- **Security Features**:
  - Permission checking based on target type
  - Parameter validation and sanitization
  - Safe action type enforcement

#### `setting_changer.php`
- **Purpose**: Execute setting change actions on courses, sections, and modules
- **Supported Settings**:
  - **Course**: `visible`, `enablecompletion`, `showgrades`, `groupmode`, etc.
  - **Section**: `visible`, `availability`
  - **Module**: `visible`, `completion`, `groupmode`, `indent`, etc.
- **Safety Features**:
  - Whitelist of allowed settings
  - Value type conversion and validation
  - Event triggering for audit trail

#### `content_adder.php`
- **Purpose**: Execute content addition actions
- **Supported Content Types**:
  - **Sections**: Add new course sections
  - **Modules**: `label`, `url`, `page`, `forum`, `assign`, `quiz`, `resource`
- **Features**:
  - Module availability checking
  - Default content generation
  - Proper module configuration
  - Cache rebuilding

## Supported Action Types

### 1. Change Setting (`change_setting`)
Changes configuration settings for courses, sections, or modules.

**Example Use Cases**:
- Make course visible (setting='visible', value='1') → Shows "Make visible"
- Enable completion tracking (setting='enablecompletion', value='1') → Shows "Enable completion"  
- Set module to show description (setting='showdescription', value='1')
- Enable groups (setting='groupmode', value='1') → Shows "Enable groups"

### 2. Add Content (`add_content`)
Adds new content to courses or sections.

**Example Use Cases**:
- Add a quiz to an empty section
- Create a forum for discussions
- Add a page with course information





### 3. Create Backup (`create_backup`)
Creates backups of course content.

**Example Use Cases**:
- Backup course before major changes
- Create archive for compliance
- Generate restore point

## Security Considerations

### Permission System
- **Course Actions**: Require `moodle/course:update` capability
- **Section Actions**: Require `moodle/course:update` capability for parent course
- **Module Actions**: Require `moodle/course:manageactivities` capability
- **Backup Actions**: Require `moodle/backup:backupcourse` capability

### Validation Layers
1. **Type Validation**: Ensure action type is supported
2. **Target Validation**: Verify target exists and user has access
3. **Parameter Validation**: Check required parameters are present and valid
4. **Safety Validation**: Ensure action is safe to perform
5. **Permission Validation**: Verify user capabilities

### Safe Execution
- Only whitelisted settings can be changed
- Content types are validated against available modules
- Database transactions ensure consistency
- Events are triggered for audit trail
- Error handling prevents system damage

## Usage Example

```php
use block_course_audit\actions\action_validator;
use block_course_audit\actions\setting_changer;

// Validate action
$validator = new action_validator();
$params = [
    'action' => 'change_setting',
    'target_type' => 'course',
    'target_id' => 123,
    'setting' => 'visible',
    'value' => '1'
];

$validation = $validator->validate_action($params);
if ($validation['success']) {
    // Execute action
    $changer = new setting_changer();
    $result = $changer->execute_action($params);
    
    if ($result['success']) {
        echo "Action completed: " . $result['message'];
    } else {
        echo "Action failed: " . $result['message'];
    }
}
```

## Adding New Action Types

To add a new action type:

1. **Add to Action Generator**: Create new `generate_[type]_action()` method
2. **Add to Action Validator**: Add validation logic in `validate_specific_action()`
3. **Create Handler Class**: Implement execution logic in new handler class
4. **Add Language Strings**: Define user-facing messages
5. **Update Documentation**: Document the new action type

## Error Handling

All action handlers return standardized result arrays:

```php
[
    'success' => bool,      // True if action succeeded
    'message' => string     // User-friendly message
]
```

Error messages are internationalized and provide clear feedback to users about what went wrong and why.
